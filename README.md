# 꼬리에 꼬리 물기

## 공개 앱 (방문자 개인 사용)

- 배포 주소: https://kkokkomoo.streamlit.app/
- 공개 `app.py`에는 발표자료 등록 → 질문 → 답변 → 꼬리질문 → 피드백 → 기록 다운로드만 표시합니다.
- 방문자는 **무료 규칙 기반 데모**를 체험하거나 자신의 **OpenAI API 키**를 세션에 입력해 실제 AI 생성 기능을 사용합니다. ChatGPT 구독은 API 사용료를 포함하지 않습니다.
- **운영자의 API 키를 공유·사용하지 않습니다.** AI 모드에서 각 방문자의 키로 요청하며 별도 API 요금이 발생할 수 있습니다. 키는 세션 메모리에서만 사용하고 로그/다운로드에 포함하지 않습니다. 세션 종료 또는 '키 연결 해제' 시 없어집니다.
- `dev_app.py`는 개발자 로컬 검증·디버깅 도구입니다. **공개 Streamlit 앱은 반드시 `app.py`만 배포**하세요. 개발자 검증용 코드와 과거 질문 데이터는 일반 사용자 UI에 나오지 않습니다.
- AI 기능을 실제로 쓰려면 본인에게 API 키와 API 결제 설정이 필요합니다. 단순한 ChatGPT 계정 연결 기능은 없습니다.


Python + Streamlit 발표 Q&A 연습 앱. 발표 자료에 근거한 첫 질문 → 직접 답변 → 답변에 연결된 꼬리질문 → 피드백·평가·기록 다운로드를 지원합니다. 화면과 문서는 한국어입니다.

## 실행

Python 3.11 이상을 권장합니다. 프로젝트 폴더에서 실행하세요.

```bash
python -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

브라우저에서 `http://localhost:8501` 접속 후 **자료 관리 → 예제 자료로 체험하기 → Q&A 연습 → 새 연습 시작**을 선택하세요. 기본값은 API 키가 필요 없는 데모입니다.

OpenAI 모드를 사용하려면 실행 셸의 환경변수를 설정하고 앱을 재시작하세요.

```bash
export OPENAI_API_KEY='본인의 키'
export OPENAI_MODEL='gpt-4o-mini'
streamlit run app.py
```

PowerShell에서는 `$env:OPENAI_API_KEY='본인의 키'`로 설정합니다. `.env.example`은 설명용이며 `.env`를 자동으로 읽지 않습니다. 키를 코드·브라우저 입력란·Git에 저장하지 않습니다. Structured Outputs를 지원하는 모델이 필요하며 API 비용이 발생합니다.

## Streamlit Community Cloud 배포

PR을 `main`에 병합한 후 Streamlit Community Cloud에서 **Create app**을 선택하고 아래 값을 지정합니다. PR을 먼저 검토하려면 브랜치만 PR의 작업 브랜치로 지정할 수도 있습니다.

| 설정 | 값 |
|---|---|
| Repository | `osnuoeh/kkokkomoogi` |
| Branch | `main` (PR 병합 후) |
| Main file path | `app.py` |
| Python version | `3.12` 권장 (이번 검증 환경) |
| Dependency file | 저장소 루트 `requirements.txt` (자동 감지) |

`app.py`와 `qa/` 패키지는 저장소 루트에 있습니다. 앱은 환경변수 없이 데모로 시작합니다. 별도 빌드 명령이나 `packages.txt`는 현재 필요하지 않습니다. `.streamlit/config.toml`에는 고정 주소·포트를 두지 않고 25MB 업로드 제한과 headless 모드만 지정했습니다. Cloud가 제공하는 실행 주소·포트를 따릅니다. 테스트 도구는 배포 의존성과 분리한 `requirements-dev.txt`에 있습니다.

OpenAI 기능을 켜려면 앱의 **Advanced settings → Secrets** 또는 배포 후 **Settings → Secrets**에서 다음과 같이 **최상위 TOML 키**를 입력합니다. 실제 키는 Cloud 설정 화면에만 넣고 저장소에는 넣지 않습니다.

```toml
OPENAI_API_KEY = "여기에_실제_키를_입력"
OPENAI_MODEL = "gpt-4o-mini"
```

이 예시는 자리표시자입니다. `[openai]` 같은 테이블 아래에 넣으면 현재 코드가 읽는 환경변수에 연결되지 않습니다. Streamlit의 최상위 Secrets는 환경변수로 노출되므로 현재 `os.getenv` 코드로 사용할 수 있습니다. 로컬 Secrets는 `.streamlit/secrets.toml`에 둘 수 있으며 Git에서 제외됩니다. 키를 변경한 후 앱을 재시작하고 사이드바에서 **OpenAI API**를 선택하세요. 데모만 배포하려면 Secrets를 비워 둡니다.

배포 후에는 예제 질문·답변·꼬리질문·기록 다운로드를 먼저 확인하고, 허가된 소규모 발표 자료로 파일 업로드와 API 호출을 추가 확인하세요. 실제 Community Cloud 배포 및 실 API 호출은 이번 검증에 포함하지 않았습니다. 최신 의존성은 범위 안에서 다시 설치되므로 배포 로그에서 Python 버전과 설치 오류도 확인해야 합니다.

### 공개 범위·비용·자료 보관

- API 키를 설정한 앱에서는 접근 가능한 모든 사용자가 서버의 키로 API 요청을 발생시킬 수 있습니다. 현재 앱에는 로그인·사용자별 할당량·호출 속도 제한이 없습니다. 개인 연습용이면 Cloud에서 제공하는 접근 제한을 적용하고, 공개 체험판이면 키 없는 데모 배포를 권장합니다. 제공 모델 접근 권한과 OpenAI 프로젝트 사용량·지출 알림도 설정하세요.
- 업로드 자료는 실행 중인 Cloud 서버의 세션 메모리에서 처리되며 API 모드에서는 선택된 텍스트·답변이 OpenAI로 전송됩니다. 공개 권한이 없는 논문/발표 자료는 해당 처리 경로의 이용 가능 여부를 확인하세요. 앱은 업로드를 GitHub나 영구 저장소로 전송하지 않습니다.
- Cloud 재시작·휴면·연결 종료 시 메모리의 기록이 사라질 수 있습니다. 종료 전 Markdown/CSV/JSON을 다운로드하세요. 많은 파일이나 동시 사용자는 메모리 한도에 도달할 수 있으므로 작은 문서부터 확인하세요.
- 실제 발표 파일·과거 질문·답변 파일은 저장소 밖 또는 무시되는 `uploads/`, `data/`, `reports/`, `sessions/`에 보관하세요. TXT/Markdown 질문 파일도 이 폴더에 두세요. 업로드한 자료와 다운로드 기록을 PR에 첨부하지 마세요.

## 구현 범위

- Phase 1: PDF/PPTX 텍스트 추출, 파일/페이지/슬라이드 유지, 발표와 참고 구분, 청중/난이도 설정, 한 질문씩 진행, 실제 답변 기반 꼬리질문, 주제 전환, 답변 후 피드백, 인용 원문 확인, Markdown 기록.
- Phase 2: CSV/XLSX/TXT/Markdown 과거 질문 업로드, 당시 답변·피드백 등 메타데이터, 예시 CSV, 생성 후 독립 의미 비교, 과거 질문별 충족/누락 표시.
- Phase 3 기본: 질문 5개 항목 보조 평가, 사람 점수 별도 저장, 오류 유형/개선 메모, 생성 프롬프트 버전과 원문 기록, 새 프롬프트 실험, 실험별 평균·표본 수·간단한 그래프, Markdown/CSV/JSON 다운로드.
- Phase 4: 파서·데이터 분리·Q&A 상태·평가·내보내기·Streamlit UI 자동 테스트. 실제 API 호출 및 실제 발표 자료의 의미적 품질은 미검증입니다.

AI 점수는 정답이 아닙니다. 사람이 AI 원점수와 별개로 점수와 피드백을 저장할 수 있습니다. 판정할 수 없는 항목은 `검토 필요`이며, 첫 질문의 논리적 연결성도 채점하지 않습니다.

## 실제 발표 자료로 테스트

1. **자료 관리**에서 발표 PPTX/PDF와 참고 논문 PDF를 각각 업로드하고 **업로드한 자료 적용**을 누릅니다. 새 자료 적용은 이전 실험과 평가 질문을 초기화하므로 먼저 기록을 다운로드하세요.
2. **추출 원문 확인**에서 페이지별 텍스트와 누락을 확인합니다. 텍스트가 없는 페이지는 OCR이 필요합니다. 그래프/수식/이미지 자체를 해석하지 않으므로 해당 질문은 사람이 확인해야 합니다.
3. **예시 CSV 다운로드** 양식에 과거 질문과 당시 답변·피드백을 입력하고 업로드합니다. 여러 파일을 합쳐 등록할 수 있습니다. 이미 사용 중인 질문 목록은 새 목록으로 교체됩니다.
4. **Q&A 연습**에서 청중·난이도를 지정하고 첫 질문을 생성합니다. 답변을 제출한 뒤 **답변 피드백 받기**, **다음 질문 생성**을 선택합니다. 주제를 바꾸려면 새 주제를 입력합니다.
5. **질문 검증 및 디버깅**에서 과거 질문과 비교하고, 질문을 선택해 품질 평가와 사람의 점수·오류 유형·개선 의견을 저장합니다. 의미 비교는 OpenAI 모드에서만 동작합니다.
6. 추가 생성 지침을 수정하고 **프롬프트 버전 저장 → 저장한 프롬프트로 새 실험 생성**을 누릅니다. 같은 자료·청중·난이도를 사용하고 가능한 한 동일한 답변 조건으로 실험합니다. 재테스트도 한 번에 하나의 질문만 보여줍니다.
7. 실험 선택에서 이전/이후 기록을 열어 검토하고 평균과 표본 수를 비교합니다. 점수 차이는 통계적 성능 개선의 증거가 아닙니다. 소수 사례에서 더 나아 보여도 여러 발표·청중·반복 실험으로 확인하세요.
8. **기록 다운로드**에서 Markdown, 평가 CSV, 전체 JSON을 저장합니다. 비교 표의 CSV는 디버깅 탭에서 별도로 다운로드할 수 있습니다.

### 질문 데이터 형식

CSV는 UTF-8 또는 UTF-8 BOM, XLSX는 첫 워크시트·첫 행 헤더를 사용합니다. `question`(또는 `질문 내용`/`질문`) 열이 필수입니다. 파일당 최대 1,000개 질문, 한 번의 비교는 과거/생성 질문 각각 100개까지입니다. 예시는 `examples/example_questions.csv`에 있습니다.

| 영문 열 | 한국어 열 | 설명 |
|---|---|---|
| topic | 발표 주제 | 발표 주제 |
| material | 자료 이름 | 발표 파일 이름 |
| question | 질문 내용 | 질문 본문 (필수) |
| source | 질문 출처 | 실제 청중 질문 / 사전 예상질문 / AI 생성 질문 |
| type | 질문 유형 | 개념 / 원리 / 그래프 해석 / 실험 근거 / 한계 / 응용 |
| answer | 당시 답변 | 선택 |
| feedback | 피드백 | 선택 |
| reference | 관련 참고 문헌 | 선택 |
| page | 페이지 | 선택 |

TXT/Markdown은 비어 있지 않은 한 줄을 질문 하나로 처리합니다. `#` 제목과 번호·목록 접두사는 제외합니다. Markdown 표 및 여러 줄 답변의 구조화 파싱은 지원하지 않으므로 답변/피드백은 CSV/XLSX의 열로 정리하세요. 자유 형식의 당시 답변 파일을 질문과 자동 연결하지 않습니다.

## 데이터 분리와 근거 처리

`qa/engine.py`의 생성 함수는 문서, 실제 Q&A, 청중, 난이도, 새 주제, 추가 프롬프트만 받습니다. 과거 질문 인자가 없습니다. 기존 턴에서 질문·사용자 답변만 명시적으로 골라 생성 요청에 넣으므로 평가 결과·사람 피드백·과거 정답은 생성 문맥에 포함되지 않습니다. 독립 API 요청인 `qa/evaluation.py`에서 생성 후 과거 질문을 비교하며 모델 대화를 공유하지 않습니다.

과거 질문이나 모범답안을 발표 문서 또는 추가 프롬프트에 직접 붙여 넣으면 이러한 분리가 무의미해집니다. 평가 데이터는 전용 업로더에만 넣으세요. API 모드에서 문서·질문·답변은 생성/피드백 요청으로, 과거 질문은 비교 요청으로 OpenAI에 전달됩니다.

문서에서 최대 22,000자의 문맥을 선택합니다. 한 페이지당 최대 2,500자, 발표/참고에서 우선 하나씩 포함하고 관련 어휘와 한국어 2글자 조각을 기준으로 나머지를 선택합니다. 긴 문서는 전체를 읽지 않으며, 긴 대화는 최근 12개 턴만 생성 문맥에 들어갑니다. 선택된 페이지 ID·길이·문맥 해시를 JSON에 기록합니다. 범용 검색 시스템의 완전성이나 모든 개념의 커버리지를 보장하지 않습니다.

모델이 반환한 `page_id`와 `quote`를 실제 전달한 발췌와 대조합니다. 잘못된 인용은 제거하고 근거 부족으로 표시합니다. 유효한 인용이 있어도 질문의 전제나 과학적 타당성이 자동으로 증명되지는 않습니다. 원문 확인/모델 추론/근거 부족 구분은 모델 판단도 포함하므로 사람이 확인해야 합니다.

## 데모와 실제 검증의 차이

예제 문헌은 가상의 시연용 텍스트이며 실제 논문이 아닙니다. 데모는 문서 발췌와 실제 답변을 넣는 규칙 기반 생성기입니다. 청중·난이도·추가 프롬프트는 기록되지만 데모 생성에 의미적으로 적용되지 않습니다. 데모 품질 점수는 모두 검토 필요이며 비교 표도 어휘 중첩 후보만 표시합니다. 이를 의미 기반 비교·커버리지·실제 성능으로 해석하면 안 됩니다.

OpenAI 모드에서는 별도의 LLM 평가 요청으로 의미와 핵심 개념을 비교합니다. 이 평가도 편향이나 오류가 있을 수 있습니다. 현재 버전은 독립 인간 전문가의 평가, 임베딩 검색, 통계적 A/B 실험, 자동 프롬프트 최적화까지 구현하지 않았습니다. 수정 프롬프트 재테스트는 새 실험을 만들고 사용자가 답변하는 방식입니다.

## 저장 및 보안

업로드 파일은 디스크에 자동 저장하지 않고, 추출 텍스트·질문·답변·평가를 사용자 세션 메모리에 저장합니다. 새로고침/연결 종료/서버 재시작으로 기록이 사라질 수 있으므로 종료 전에 다운로드하세요. JSON은 보관/분석용이며 다시 업로드해 세션을 복원하는 기능은 없습니다. 최근 비교 결과만 유지하므로 다른 실험으로 전환하기 전에 비교 CSV를 저장하세요.

GitHub 업로드/commit/push/외부 저장 자동화는 없습니다. `.gitignore`는 `.env`, 자료 PDF/PPTX/XLSX/CSV, uploads/data/reports/sessions 폴더와 일반적인 기록 파일을 제외합니다. 실제 자료와 다운로드 기록은 해당 전용 폴더 또는 저장소 바깥에서 보관하고 `git add -f`를 사용하지 마세요. Git 무시 규칙은 이미 추적 중인 파일을 보호하지 않으므로 게시 전 `git status`도 확인하세요. 예외로 허용하는 CSV는 가상 질문 예제 하나입니다.

서버 주소·포트는 배포 환경의 설정을 따르고 Streamlit 사용 통계 전송은 껐습니다. 로컬에서만 접근하도록 실행하려면 `streamlit run app.py --server.address 127.0.0.1`을 사용하세요. 공용 호스팅용 인증·영구 DB·사용자 격리 운영 검증은 포함하지 않습니다. API 오류 원문과 키는 UI나 앱 로그에 출력하지 않습니다. PDF/Office 파싱 오류, 암호화 문서, 이미지 문서는 사용자에게 안내하며 Office 압축 크기 제한을 적용합니다. PDF 파서는 악성 문서를 완전히 격리하는 샌드박스가 아니므로 신뢰할 수 있는 파일을 사용하세요.

## 자동 테스트

프로젝트 폴더에서 실행합니다.

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

테스트는 외부 API를 호출하지 않습니다. SDK 구조화 응답 테스트도 HTTP 모의 전송입니다. 실행 결과와 미검증 항목은 `VALIDATION.md`를 참고하세요.

# 꼬리에 꼬리 물기 — Gemini BYOK 발표 연습

기존 발표 Q&A·페이지 근거·기록 다운로드와 개발자 평가 도구를 유지하면서, 공개 앱의 실제 AI를 **사용자가 연결한 Gemini 키**로만 호출합니다. 공개 URL은 **https://kkokkomoo.streamlit.app/**, 저장소는 `osnuoeh/kkokkomoogi`, 진입점은 계속 `app.py`입니다.

## 실행과 사용자 흐름

Python 3.12를 권장합니다.

```bash
python -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

1. **나의 Gemini 연결**에서 [Google AI Studio](https://aistudio.google.com/api-keys)의 개인 키를 비밀번호 창에 입력합니다. 서버 전송/비용 안내에 동의하고 **연결하기**를 누릅니다.
2. 모델 메타데이터 조회 성공을 표시합니다. 이는 생성 성공·잔여 할당량·무료 등급을 검증한 것은 아닙니다. 실제 응답 성공 후에만 **AI 생성 질문/피드백**으로 표시합니다.
3. 연결 후 설정은 연결 관리 안으로 접고 자료 업로드와 연습을 중심으로 보여줍니다. 자료/참고 문헌을 등록하고 청중·난이도를 고른 뒤 시작합니다.
4. 답변을 제출하면 관련성·정확성·근거·누락·다음 쟁점을 먼저 분석합니다. 주제 이탈/오개념이면 수정 기회를 제공하고, 부분 답변이면 빠진 원리, 충분한 답변이면 조건/예외/한계를 심화합니다. 한 번에 한 질문이며 답변 전에 모범답안을 제공하지 않습니다.
5. **답변 수정하기**로 재답변할 수 있고 Markdown/JSON으로 기록을 다운로드합니다. 키 없이 시작하려면 별도로 **규칙 기반 체험**을 선택합니다. 이는 의미 이해를 하지 않는 템플릿 체험이며 실제 AI가 아닙니다.

## 공식 모델/SDK 확인

공식 `google-genai` Python SDK를 사용합니다. 기본 ID는 요청한 **`gemini-3.8-flash`**입니다. 2026-11-06 공식 모델 문서에서 모델 ID·텍스트/이미지/PDF 입력·구조화 출력 지원을 확인했습니다. 실제 키별 사용 가능 여부는 런타임 `models.get`으로 조회합니다.

- [Gemini 3.8 Flash 공식 모델](https://ai.google.dev/gemini-api/docs/models/gemini-3.8-flash)
- [최신 모델/마이그레이션](https://ai.google.dev/gemini-api/docs/latest-model)
- [PDF 이해](https://ai.google.dev/gemini-api/docs/document-processing)
- [구조화 출력](https://ai.google.dev/gemini-api/docs/structured-output)
- [공식 Python SDK](https://github.com/googleapis/python-genai)

현재 구현은 공식 SDK의 `models.generate_content`와 JSON schema를 사용합니다. 3.x에는 low thinking, 출력 최대 4096 토큰, 재시도 1회 시도(자동 재시도 없음)를 적용하고 3.8에서 지원하지 않는 sampling/minimal 설정은 넣지 않습니다. SDK/공식 API가 앞으로 변경되면 다시 검증해야 합니다.

기본 모델을 조회할 수 없으면 같은 키로 조회한 생성 가능한 Flash 대안을 최대 5개 안내합니다. 사용자가 대안과 비용 조건에 동의한 경우에만 해당 모델을 연결합니다. 연결 관리에서도 직접 대안 조회를 요청할 수 있습니다. **모델/요금 변경을 자동으로 하지 않습니다.** 대안도 메타데이터 조회 결과일 뿐 생성/무료 사용 보장은 아닙니다. 일반 사용자는 모델 ID나 프로젝트 설정을 직접 입력하지 않습니다.

## 할당량·비용과 키 보안

- A의 요청은 A가 연결한 키, B의 요청은 B가 연결한 키로만 보냅니다. 할당량은 **키가 속한 Google 프로젝트**에 적용되므로 같은 프로젝트의 키는 한도를 공유할 수 있습니다. [공식 한도](https://ai.google.dev/gemini-api/docs/rate-limits)
- 키만으로 Free/Paid 등급을 판정하지 않습니다. 무료 등급은 모델별 이용 범위/할당량이 제한되고, 유료 프로젝트 키로 요청하면 비용이 발생할 수 있습니다. Google 로그인이나 Gemini 유료 구독이 개인 API 할당량을 연결하는 기능은 아닙니다. [공식 요금](https://ai.google.dev/gemini-api/docs/pricing) · [청구](https://ai.google.dev/gemini-api/docs/billing/)
- 429는 할당량/요청 제한으로 안내하며 유료 모델이나 운영자 키로 대신하지 않습니다. 인증 실패/만료는 키를 삭제하고 재연결을 안내합니다. 요청 실패는 원문 오류를 표시하지 않고 기록을 보존하며 자동으로 데모 성공 결과를 만들지 않습니다.
- 키는 이 앱 서버로 전송되어 해당 Streamlit 세션 메모리에서만 사용합니다. 소스·URL·로그·다운로드·전역 캐시에 넣지 않습니다. 앱에 키를 localStorage/쿠키로 저장하는 코드는 없습니다. 비밀번호 입력 위젯은 제출 시 지우고 **연결 해제** 시 연결 키/대안 대기 키를 삭제합니다. 연결 해제는 이미 전송 중인 Google 요청의 취소를 보장하지 않습니다.
- 연결 검사는 모델 조회만 하며 생성 probe를 보내지 않습니다. 세션 종료/서버 재시작 후 다시 연결해야 합니다. 서버의 `GEMINI_API_KEY`, `GOOGLE_API_KEY`, `OPENAI_API_KEY`를 공개 요청에 자동으로 사용하지 않으며 `vertexai=False`로 ADC/Vertex 인증 경로도 사용하지 않습니다.
- 공개 BYOK 경로에는 Redis/공용 OpenAI 활성화 설정이 필요 없습니다. 이전 `public_ai.py`/`quota.py`는 호환 코드/테스트로 남지만 공개 앱에서 import하지 않습니다. 개발자 도구를 별도 로컬 실행했을 때만 개발자 환경변수 키를 사용합니다.
- 비정상 반복 완화를 위해 세션당 생성/분석 요청 100회, 사용자 동작 간 2초, 프로세스 동시 생성 4개를 제한합니다. 답변 분석+다음 질문은 최대 두 번의 요청일 수 있고 실패도 로컬 카운터에 포함합니다. 초기화/재연결로 카운터를 지우지 않습니다. 이 제한은 메모리 기반의 보조 장치이며 새 세션/서버 재시작으로 달라질 수 있어 인증·봇 방어·금액 상한을 대체하지 않습니다. 비용/할당량의 최종 권한은 각 키의 Google 프로젝트에 있습니다. 공개 호스팅 리소스 보호는 별도 게이트웨이/접근 제한도 검토해야 합니다.
- 무료/유료의 Google 데이터 처리 조건이 다를 수 있습니다. 무료 서비스에서는 입력/응답이 제품 개선에 사용될 수 있으므로 민감·비공개 자료를 전송하기 전에 조건을 확인하세요. 앱의 세션 보관 방식과 Google의 데이터 보관을 동일하게 가정하지 않습니다. [공식 데이터 조건](https://ai.google.dev/gemini-api/terms)

## PDF 그래프·이미지와 PPTX

PDF 텍스트만으로는 Voltage Profile/XRD/반응 모식도를 이해할 수 없습니다. **PDF 페이지도 분석**을 선택하면 내용 점수로 추천한 페이지를 사용자가 수정해 최대 4페이지를 고릅니다. PDFium으로 서버 메모리에서 실제 페이지를 JPEG로 변환해 Gemini에 inline 이미지로 보냅니다. 장변 최대 1200px, 전체 이미지 최대 4MB이며 출력·텍스트 크기도 제한합니다. 원본 전체 PDF를 Files API에 올리거나 전역 캐시로 공유하지 않습니다.

파일명/물리 페이지/안정적인 page_id를 이미지와 함께 전달합니다. 시각 인용은 실제 전달한 페이지에만 허용하고, 텍스트 문자열로 검증한 근거와 구분해 **시각 해석·자동 검증 안 됨**으로 표시/내보냅니다. 축·범례·해상도·인과 추론의 불확실성을 모델이 설명하도록 합니다. 실제 시각 정확성은 사람이 원본과 대조해야 합니다. 이미지 기반 문서는 시각 분석 페이지를 선택해야 실제 분석이 가능합니다. 선택하지 않으면 이미지/그래프를 읽었다고 표시하지 않습니다.

발표 PDF/PPTX·참고 PDF는 기존 파일당 25MB/500페이지 제한을 유지합니다. 스캔 PDF도 시각 입력으로 사용할 수 있지만 내용 없는 표지는 질문 근거가 되지 않도록 모델에 지시합니다. **PPTX는 텍스트만 추출**하며 서버에 LibreOffice 등이 있다고 가정하지 않습니다. 사용자가 PDF로 내보내 다시 업로드해야 시각 분석이 가능합니다.

## 개발자 도구 — localhost 전용 명시 실행

개발자 화면의 **검증 제공자 → Gemini**, **질문 생성 방식 → Gemini API**를 선택합니다. 로컬 환경변수 `GEMINI_API_KEY`와 선택 `GEMINI_MODEL`(기본 `gemini-3.8-flash`)을 사용하며 공개 앱의 방문자 키와 섞지 않습니다. 개발자 키의 할당량/비용은 개발자가 관리합니다. OpenAI 호환 제공자 선택 시에만 기존 `OPENAI_API_KEY`/`OPENAI_MODEL` 경로를 사용할 수 있습니다. Gemini 실패 시 OpenAI로 전환하지 않습니다. 규칙 체험은 실제 AI가 아닙니다.

Gemini를 선택하면 개발 도구에서도 PDF 시각 페이지를 선택해 평가할 수 있습니다. 그림 데이터와 provider/model 조건도 구분해서 실험하세요. 같은 엔진을 사용하지만 모의 테스트나 개발 점수를 실제 사용자 품질로 해석하지 마세요.

```bash
pip install -r requirements-dev.txt
KKOKKOMOOGI_DEV_LOCAL=1 streamlit run dev_app.py --server.address 127.0.0.1 --server.port 8502
```

PowerShell:

```powershell
$env:KKOKKOMOOGI_DEV_LOCAL='1'
streamlit run dev_app.py --server.address 127.0.0.1 --server.port 8502
```

환경변수와 localhost 바인딩이 모두 있어야 도구가 열립니다. 이는 로컬 실행 실수를 막는 가드이며 인터넷 공개용 인증 시스템은 아닙니다. 프록시/터널로 개발 도구를 외부에 노출하지 마세요. 공개 `app.py`에서는 이 환경변수나 URL 매개변수·숨김 버튼으로 개발 기능을 활성화할 수 없습니다. `pages/` 자동 멀티페이지 폴더도 만들지 않습니다.

### 데이터셋 등록과 수동 검증

1. 개발 도구의 자료 관리에서 과거 발표와 참고 논문을 적용합니다. 예제 버튼은 가상의 발표/문헌/질문만 불러옵니다.
2. 예시 CSV를 다운로드하고 과거 실제 청중 질문·예상질문·당시 답변·피드백을 평가 전용 업로더에 등록합니다. 실제 자료는 로컬의 `datasets/` 등 무시 폴더 또는 저장소 바깥에 보관합니다.
3. Q&A 연습에서 첫 질문과 실제 입력 답변에 대한 꼬리질문을 생성합니다. 기존 질문과 비교, 질문별 품질, 사람 점수·오류 유형·개선 메모를 검토합니다.
4. 추가 생성 지침을 저장하면 프롬프트 버전을 기록합니다. 새 실험을 만들어 이전/이후를 비교합니다.
5. Markdown/CSV/JSON으로 기록을 저장합니다. 자료/평가 질문을 교체하면 이전 자동 평가 결과를 초기화해 데이터셋이 섞이지 않도록 합니다.

### 답변 없는 첫 질문 자동 반복 평가

**자동 반복 평가** 탭에서 데이터셋 이름·청중·난이도·기준/후보 지침·반복 횟수(버전별 1~5회)를 정하고 실행합니다. 시나리오를 선택하지 않으면 각 반복은 **빈 대화에서 독립 첫 질문 하나**를 생성하므로 직접 답변할 필요가 없습니다.

두 버전 모두 동일한 자료·평가 질문·설정·모델·시나리오 스냅샷으로 실행합니다. 자료/평가목록/시나리오 해시, 엔진 코드 해시, 조건 ID, 프롬프트 원문·버전, 반복 번호를 저장합니다. 모든 질문 생성이 끝난 뒤 품질 평가 및 과거 질문 의미 비교를 별도 요청으로 수행합니다. 중간 실패는 성공 점수로 변환하지 않고 오류/미채점으로 보존합니다.

### 준비된 발표자 답변 시나리오 재생

시나리오 재생을 체크하고 다음 형식의 JSON 파일을 전용 업로더에 넣습니다. 화면에서 가상 예시도 다운로드할 수 있습니다.

```json
[
  {"answer": "검증 손실이 증가했기 때문에 과적합을 의심합니다.", "note": "개발자 메모"},
  {"answer": "외부 데이터 검증이 없어 일반화를 단정할 수 없습니다.", "note": "두 번째 고정 답변"}
]
```

답변은 1~5개, 개별 12,000자 이하입니다. 첫 질문 생성 → 첫 답변 주입 → 꼬리질문 생성 → 다음 답변 주입 순서이며, 답변 N개에 질문 N+1개를 생성합니다. 과거 질문 파일의 `answer` 열을 자동으로 시나리오로 사용하지 않습니다. `note`, 미래 답변, 과거 질문·당시 모범답안은 생성기에 전달하지 않습니다.

고정 답변은 생성 질문에 적합하지 않을 수 있으므로 질문·재생 답변을 사람이 함께 검토해야 합니다. 이러한 결과는 실제 사용자의 자유 답변에 대한 질문 품질 검증과 구분합니다. 마지막 질문은 미답변으로 남습니다.

개발 리포트는 질문별 5개 항목 평가, 원문 근거, 기존 질문별 개념 커버리지, 문장 동일 중복 후보, 오류, 조건과 답변 출처를 포함합니다. 문장 동일 후보는 의미적 다양성 점수가 아닙니다. AI 점수는 1~5 또는 검토 필요이며 사람이 수동 검증 화면에서 별도 점수를 저장할 수 있습니다. 데모는 점수를 모두 검토 필요로, 의미 비교는 어휘 중첩 후보로만 표시합니다. 점수 차이가 통계적 개선을 입증하지는 않습니다. 실행 전 예상 API 호출 수를 표시하며, 반복과 시나리오 길이에 따라 비용·시간이 늘어납니다.

### 평가 질문 형식

CSV는 UTF-8/BOM, XLSX는 첫 워크시트의 첫 행을 헤더로 사용합니다. 파일당 최대 1,000개, 한 번의 비교는 기존/생성 질문 각각 최대 100개입니다. `examples/example_questions.csv`는 가상 예시입니다.

| 영문 열 | 한국어 열 | 내용 |
|---|---|---|
| topic | 발표 주제 | 발표 주제 |
| material | 자료 이름 | 발표 파일 |
| question | 질문 내용 / 질문 | 필수 질문 본문 |
| source | 질문 출처 | 실제 청중 질문 / 사전 예상질문 / AI 생성 질문 |
| type | 질문 유형 | 개념 / 원리 / 그래프 해석 / 실험 근거 / 한계 / 응용 |
| answer | 당시 답변 | 선택, 평가 경로에만 보관 |
| feedback | 피드백 | 선택 |
| reference | 관련 참고 문헌 | 선택 |
| page | 페이지 | 선택 |

TXT/Markdown은 제목을 제외한 한 줄을 질문 하나로 읽습니다. 여러 줄 답변·표는 CSV/XLSX의 열로 정리하세요. 별도 답변 문서를 질문에 자동 연결하지 않습니다.

## 엔진 공유와 입력 분리

공개 앱·개발 앱·자동 반복 실행은 모두 `qa.engine.generate`를 사용합니다. 자료 검색·API 호출·구조화 출력·인용 검사는 하나의 구현입니다. Gemini 요청은 ContextVar에 명시적인 키·모델·이미지·세션 미터만 두고 요청 후 해제합니다. 공개 앱은 이 경로로만 실제 AI를 호출하며 운영자 환경변수나 Vertex/ADC 인증으로 대신하지 않습니다. 개발 요청/다른 사용자의 스레드로 키나 문서를 섞지 않습니다. 공개 앱은 검토된 `qa/prompts.py`의 `PRODUCTION_INSTRUCTIONS`만 사용합니다. 후보 프롬프트를 실제 배포에 반영하려면 해당 상수를 수정해 테스트·코드 리뷰·PR 병합을 거쳐야 합니다. 개발 화면에서 후보를 저장하는 것만으로 공개 앱이 바뀌지 않습니다.

생성 함수는 문서와 질문/실제 답변만 명시적으로 골라 받으며 평가 데이터셋 인자가 없습니다. 독립 평가자만 과거 질문을 읽습니다. 자동 반복 실행도 전체 데이터셋을 생성기에 넘기지 않습니다. 개발자 메모·평가·사람 피드백은 대화 문맥에서 제외합니다. 평가 정답을 직접 발표 문서나 지침에 붙여 넣으면 코드만으로 막을 수 없으므로 입력 자체를 분리해야 합니다.

문서 문맥은 최대 22,000자, 페이지당 최대 2,500자이며 발표/참고에서 우선 하나씩 포함한 뒤 관련 어휘로 선택합니다. 생성은 최근 12개 턴을 사용합니다. 긴 자료의 모든 개념을 읽었다고 볼 수 없으며 인용·개념 누락을 직접 확인해야 합니다.

## 데이터 보관과 Git

앱은 업로드나 평가 기록을 디스크/GitHub에 자동 저장하지 않습니다. 사용자 기록과 개발 결과는 각 앱의 세션 메모리에 보관하고 명시적 다운로드로 저장합니다. JSON은 분석·보관용이며 세션 복원 기능은 없습니다. 수동 비교는 최근 결과를 유지하므로 다른 실험 전 CSV로 저장하세요.

실제 자료·질문·답변·시나리오·리포트는 저장소 밖 또는 `datasets/`, `scenarios/`, `evaluation_results/`, `local_dev/`, `uploads/`, `data/`, `reports/`, `sessions/`에 보관합니다. 이 폴더는 TXT/Markdown을 포함해 무시됩니다. `.env`, Secrets, 자료 PDF/PPTX/XLSX/CSV/JSON, 캐시·임시 파일도 제외합니다. 이미 추적한 파일에는 무시 규칙이 적용되지 않으므로 공개 전 `git status`를 확인하고 `git add -f`로 실제 자료를 넣지 마세요.

## 기술적 질문 선택과 페이지 근거

첫 페이지를 자동으로 질문 주제로 삼지 않습니다. 전체 발표의 원문 줄을 살펴 인과/메커니즘/결과/한계 단서와 설명 분량으로 페이지를 평가합니다. 표지의 발표자·소속, 목차, 감사, 서지 목록, 독립 페이지 숫자는 후순위입니다. Introduction은 제목이 아니라 본문에 과학적 설명이 있는지로 판단하며 짧은 과학적 문장도 유지합니다. 이 규칙은 범용 의미 분류기나 과학적 검증기가 아니므로 낯선 표현·수식 위주 문서는 직접 확인해야 합니다.

질문 생성 전에 전체 발표에서 주제·주장·메커니즘·결과/한계의 **원문 후보 지도**를 만듭니다. 지도는 추출 원문이며 LLM이 검증한 요약이 아닙니다. 같은 생성 요청에서 지도와 선택 원문을 검토한 뒤 인과·반응 메커니즘·데이터 해석·한계를 질문하도록 지시합니다. 별도 LLM 분석 호출을 추가하지 않아 공개 호출 한도/예약 경로를 유지합니다.

후속 질문은 실제 답변 중 설명적 주장(앞 120자로 한정하지 않음)을 골라 질문 안에 인용하도록 합니다. 답변 인용이 빠지거나 연결 이유가 없는 LLM 응답은 표시하지 않습니다. 문자 연결 검사만으로 논리적 관련성이나 과학적 정확성이 증명되는 것은 아니며 개발자 평가 도구에서 검토해야 합니다.

원본 PDF/PPTX 객체의 페이지/슬라이드 번호는 바꾸지 않습니다. 인용은 실제 전달한 원문 발췌 또는 후보 지도에 있는 문자열과 일치해야 하며, 유효한 파일·페이지 ID만 연결합니다. PDF의 인쇄된 쪽수와 앱이 표시하는 물리적 페이지 순서는 다를 수 있습니다. 독립 숫자는 검색 개념에서 제외하되 85%, 100 cycles, Li2O처럼 본문의 수치·화학식은 원문에 유지합니다.

규칙 기반 체험은 내용 단서와 템플릿으로 질문을 만들며 실제 과학적 의미 이해/답변 평가를 하지 않습니다. 실제 LLM 결과와 구분해 표시합니다. 개발자 화면의 질문별 선택 근거에서 페이지 점수·원문 후보·답변 연결 인용을 확인할 수 있습니다. 회귀 테스트는 표지·목차·과학적 Introduction·메커니즘·가상 결과·참고문헌·감사 페이지가 있는 합성 PDF를 메모리에서 생성해 실제 PDF 파서로 읽습니다. 실제 발표 PDF는 저장소에 넣지 않습니다.

# 꼬리에 꼬리 물기

발표 자료를 읽고, 발표자의 실제 답변에서 논리적으로 이어지는 질문을 생성하는 Python + Streamlit 앱입니다. 공개 연습 앱과 로컬 개발자 검증 도구는 **같은 `qa/engine.py` 생성 엔진**을 사용합니다.

| 구분 | 공개 연습 앱 | 개발자 검증 도구 |
|---|---|---|
| 진입점 | `app.py` | `dev_app.py` |
| 목적 | 발표 Q&A 연습 | 질문 생성 품질 평가·프롬프트 개선 |
| 자료 | 발표 PPTX/PDF, 참고 논문 PDF | 발표·논문 + 평가 전용 과거 질문 + 선택 답변 시나리오 |
| 기능 | 질문 → 실제 답변 → 꼬리질문·피드백 → 기록 다운로드 | 수동 검증·사람 평가·오류 기록·동일 조건 반복 비교 |
| 실행 위치 | Streamlit Community Cloud 또는 로컬 | 명시적으로 활성화한 localhost |
| 결과 해석 | 사용자의 연습 기록과 AI 보조 피드백 | 개발용 보조 평가이며 실제 사용자 품질의 증거가 아님 |

## 공개 앱 실행

Python 3.12를 권장합니다.

```bash
python -m venv .venv
source .venv/bin/activate
# Windows PowerShell: .venv\Scripts\Activate.ps1
pip install -r requirements.txt
streamlit run app.py
```

`http://localhost:8501`에서 **예제 자료로 체험 → 연습 시작 · 첫 질문**을 선택하세요. 데모는 API 키가 필요 없는 규칙 기반 체험입니다. 데모에서 청중·난이도·추가 지침을 의미적으로 반영하거나 과학적 정확성을 판정하지 않습니다.

실제 자료는 발표 PPTX/PDF와 참고 논문 PDF를 각각 등록합니다. 파일당 25MB·500페이지 이하이며 페이지·슬라이드 번호가 유지됩니다. 이미지/스캔 문서에 텍스트가 없으면 OCR 안내를 표시합니다. 그래프·이미지·수식 자체의 시각적 의미는 분석하지 않습니다.

질문은 한 번에 하나만 제시합니다. 사용자가 답변을 제출한 뒤 피드백을 요청하거나 꼬리질문으로 이어갈 수 있습니다. 새 주제를 입력해 흐름을 바꿀 수 있습니다. 정확성·논리성·근거에 대한 AI 피드백은 보조 의견입니다. 원문 인용이 실제 추출 텍스트에 있는지 검사하지만 질문 전체의 과학적 타당성을 보장하지 않습니다.

공개 화면은 기존의 간단한 순차 연습 UI를 유지합니다. 공개 화면에는 평가 데이터 업로드, 디버깅 탭, 프롬프트 편집, 성능 비교가 없습니다. 공개 기록 다운로드도 질문·답변·피드백과 인용만 포함하며 개발자 데이터/평가 필드는 제외합니다. 자료 변경은 이전 연습 기록을 초기화하므로 먼저 Markdown/JSON을 다운로드하세요.

### 방문자 개인 OpenAI API 키

공개 앱은 기존에 반영된 **방문자 개인 키 방식**을 유지합니다. 사이드바에서 **내 OpenAI API 키로 AI 연습**을 선택하고 자신의 키를 연결합니다. 키는 현재 브라우저 세션 메모리에서만 사용하며 로그·GitHub·다운로드에 포함하지 않습니다. **키 연결 해제**는 저장한 키와 키 입력 위젯을 비우며, 키 없이 운영자 환경변수로 우회해 요청하지 않습니다. ChatGPT 구독은 API 사용료를 포함하지 않으며 방문자의 OpenAI 프로젝트에 별도 요금이 발생할 수 있습니다.

키를 넣지 않아도 무료 규칙 기반 데모를 사용할 수 있습니다. 실제 API 키의 작동 여부는 첫 요청에서 확인됩니다. Structured Outputs를 지원하는 모델과 프로젝트 사용 권한·결제 설정이 필요합니다.

## 현재 배포 URL 유지

기존 앱 **https://kkokkomoo.streamlit.app/** 을 계속 사용합니다. 이 변경은 새 Cloud 앱이나 새 URL을 만들지 않습니다. PR 병합 후 기존 Community Cloud 앱에서 아래 연결을 유지하세요.

| 설정 | 값 |
|---|---|
| Repository | `osnuoeh/kkokkomoogi` |
| Branch | `main` |
| Main file path | `app.py` |
| Python | `3.12` 권장 |
| App URL | 기존 `kkokkomoo.streamlit.app` 유지 |

기존 앱이 `main`을 추적하면 PR 병합 후 그 앱에서 업데이트됩니다. 필요하면 기존 앱을 Reboot하고 배포 로그를 확인하세요. 앱을 삭제·재생성하거나 URL 설정을 바꾸지 않습니다. `dev_app.py`를 Cloud 진입점으로 바꾸지 않고 `KKOKKOMOOGI_DEV_LOCAL`도 Cloud Secrets에 추가하지 않습니다. 이번 작업은 PR까지만 수행하며 실제 배포 업데이트는 검증하지 않았습니다.

공개 앱을 위해 운영자 `OPENAI_API_KEY`를 Cloud Secrets에 넣을 필요는 없습니다. 방문자마다 자신의 키를 입력하며, 기존에 서버 키가 있더라도 공개 UI에서는 그 키를 사용하지 않습니다. `OPENAI_MODEL`을 최상위 Secrets로 지정해 기본 모델을 변경할 수 있습니다 (기본 `gpt-4o-mini`). 환경변수와 Secrets는 키를 출력하지 않고 사용합니다. `.env.example`은 로컬 개발 설명용이며 `.env`를 자동으로 읽지 않습니다.

방문자의 키·자료는 실행 서버의 세션 메모리에서 처리되며, AI 모드에서는 선택된 텍스트·답변이 OpenAI에 전송됩니다. 연결 종료·서버 재시작·Cloud 휴면으로 키와 기록이 사라질 수 있으므로 기록은 다운로드로 보관하세요. 현재 앱에는 사용자별 인증·호출 할당량·속도 제한이 없으므로 방문자가 자신의 프로젝트 사용량과 지출 알림을 관리해야 합니다.

## 개발자 도구 — localhost 전용 명시 실행

개발용 OpenAI 평가를 실행할 때만 로컬 셸에서 `OPENAI_API_KEY`와 선택 `OPENAI_MODEL`을 설정합니다. 예: `export OPENAI_API_KEY=본인의_개발용_키`. 공개 앱의 방문자 키와 공유하지 않으며, 개발용 자동 반복 실행은 이 로컬 환경변수를 사용하는 동일 엔진을 호출합니다.

```bash
pip install -r requirements-dev.txt
KKOKKOMOOGI_DEV_LOCAL=1 streamlit run dev_app.py --server.address 127.0.0.1 --server.port 8502
```

PowerShell:

```powershell
$env:KKOKKOMOOGI_DEV_LOCAL='1'
streamlit run dev_app.py --server.address 127.0.0.1 --server.port 8502
```

환경변수와 localhost 바인딩이 모두 있어야 도구가 열립니다. 이는 로컬 실행 실수를 막는 가드이며 인터넷 공개용 인증 시스템은 아닙니다. 프록시/터널로 개발 도구를 외부에 노출하지 마세요. 공개 `app.py`에서는 이 환경변수나 URL 매개변수·숨김 버튼으로 개발 기능을 활성화할 수 없습니다. `pages/` 자동 멀티페이지 폴더도 만들지 않습니다.

### 데이터셋 등록과 수동 검증

1. 개발 도구의 자료 관리에서 과거 발표와 참고 논문을 적용합니다. 예제 버튼은 가상의 발표/문헌/질문만 불러옵니다.
2. 예시 CSV를 다운로드하고 과거 실제 청중 질문·예상질문·당시 답변·피드백을 평가 전용 업로더에 등록합니다. 실제 자료는 로컬의 `datasets/` 등 무시 폴더 또는 저장소 바깥에 보관합니다.
3. Q&A 연습에서 첫 질문과 실제 입력 답변에 대한 꼬리질문을 생성합니다. 기존 질문과 비교, 질문별 품질, 사람 점수·오류 유형·개선 메모를 검토합니다.
4. 추가 생성 지침을 저장하면 프롬프트 버전을 기록합니다. 새 실험을 만들어 이전/이후를 비교합니다.
5. Markdown/CSV/JSON으로 기록을 저장합니다. 자료/평가 질문을 교체하면 이전 자동 평가 결과를 초기화해 데이터셋이 섞이지 않도록 합니다.

### 답변 없는 첫 질문 자동 반복 평가

**자동 반복 평가** 탭에서 데이터셋 이름·청중·난이도·기준/후보 지침·반복 횟수(버전별 1~5회)를 정하고 실행합니다. 시나리오를 선택하지 않으면 각 반복은 **빈 대화에서 독립 첫 질문 하나**를 생성하므로 직접 답변할 필요가 없습니다.

두 버전 모두 동일한 자료·평가 질문·설정·모델·시나리오 스냅샷으로 실행합니다. 자료/평가목록/시나리오 해시, 엔진 코드 해시, 조건 ID, 프롬프트 원문·버전, 반복 번호를 저장합니다. 모든 질문 생성이 끝난 뒤 품질 평가 및 과거 질문 의미 비교를 별도 요청으로 수행합니다. 중간 실패는 성공 점수로 변환하지 않고 오류/미채점으로 보존합니다.

### 준비된 발표자 답변 시나리오 재생

시나리오 재생을 체크하고 다음 형식의 JSON 파일을 전용 업로더에 넣습니다. 화면에서 가상 예시도 다운로드할 수 있습니다.

```json
[
  {"answer": "검증 손실이 증가했기 때문에 과적합을 의심합니다.", "note": "개발자 메모"},
  {"answer": "외부 데이터 검증이 없어 일반화를 단정할 수 없습니다.", "note": "두 번째 고정 답변"}
]
```

답변은 1~5개, 개별 12,000자 이하입니다. 첫 질문 생성 → 첫 답변 주입 → 꼬리질문 생성 → 다음 답변 주입 순서이며, 답변 N개에 질문 N+1개를 생성합니다. 과거 질문 파일의 `answer` 열을 자동으로 시나리오로 사용하지 않습니다. `note`, 미래 답변, 과거 질문·당시 모범답안은 생성기에 전달하지 않습니다.

고정 답변은 생성 질문에 적합하지 않을 수 있으므로 질문·재생 답변을 사람이 함께 검토해야 합니다. 이러한 결과는 실제 사용자의 자유 답변에 대한 질문 품질 검증과 구분합니다. 마지막 질문은 미답변으로 남습니다.

개발 리포트는 질문별 5개 항목 평가, 원문 근거, 기존 질문별 개념 커버리지, 문장 동일 중복 후보, 오류, 조건과 답변 출처를 포함합니다. 문장 동일 후보는 의미적 다양성 점수가 아닙니다. AI 점수는 1~5 또는 검토 필요이며 사람이 수동 검증 화면에서 별도 점수를 저장할 수 있습니다. 데모는 점수를 모두 검토 필요로, 의미 비교는 어휘 중첩 후보로만 표시합니다. 점수 차이가 통계적 개선을 입증하지는 않습니다. 실행 전 예상 API 호출 수를 표시하며, 반복과 시나리오 길이에 따라 비용·시간이 늘어납니다.

### 평가 질문 형식

CSV는 UTF-8/BOM, XLSX는 첫 워크시트의 첫 행을 헤더로 사용합니다. 파일당 최대 1,000개, 한 번의 비교는 기존/생성 질문 각각 최대 100개입니다. `examples/example_questions.csv`는 가상 예시입니다.

| 영문 열 | 한국어 열 | 내용 |
|---|---|---|
| topic | 발표 주제 | 발표 주제 |
| material | 자료 이름 | 발표 파일 |
| question | 질문 내용 / 질문 | 필수 질문 본문 |
| source | 질문 출처 | 실제 청중 질문 / 사전 예상질문 / AI 생성 질문 |
| type | 질문 유형 | 개념 / 원리 / 그래프 해석 / 실험 근거 / 한계 / 응용 |
| answer | 당시 답변 | 선택, 평가 경로에만 보관 |
| feedback | 피드백 | 선택 |
| reference | 관련 참고 문헌 | 선택 |
| page | 페이지 | 선택 |

TXT/Markdown은 제목을 제외한 한 줄을 질문 하나로 읽습니다. 여러 줄 답변·표는 CSV/XLSX의 열로 정리하세요. 별도 답변 문서를 질문에 자동 연결하지 않습니다.

## 엔진 공유와 입력 분리

공개 앱·개발 앱·자동 반복 실행은 모두 `qa.engine.generate`를 사용합니다. 자료 검색·API 호출·구조화 출력·인용 검사는 하나의 구현입니다. 공개 앱은 검토된 `qa/prompts.py`의 `PRODUCTION_INSTRUCTIONS`만 사용합니다. 후보 프롬프트를 실제 배포에 반영하려면 해당 상수를 수정해 테스트·코드 리뷰·PR 병합을 거쳐야 합니다. 개발 화면에서 후보를 저장하는 것만으로 공개 앱이 바뀌지 않습니다.

생성 함수는 문서와 질문/실제 답변만 명시적으로 골라 받으며 평가 데이터셋 인자가 없습니다. 독립 평가자만 과거 질문을 읽습니다. 자동 반복 실행도 전체 데이터셋을 생성기에 넘기지 않습니다. 개발자 메모·평가·사람 피드백은 대화 문맥에서 제외합니다. 평가 정답을 직접 발표 문서나 지침에 붙여 넣으면 코드만으로 막을 수 없으므로 입력 자체를 분리해야 합니다.

문서 문맥은 최대 22,000자, 페이지당 최대 2,500자이며 발표/참고에서 우선 하나씩 포함한 뒤 관련 어휘로 선택합니다. 생성은 최근 12개 턴을 사용합니다. 긴 자료의 모든 개념을 읽었다고 볼 수 없으며 인용·개념 누락을 직접 확인해야 합니다.

## 데이터 보관과 Git

앱은 업로드나 평가 기록을 디스크/GitHub에 자동 저장하지 않습니다. 사용자 기록과 개발 결과는 각 앱의 세션 메모리에 보관하고 명시적 다운로드로 저장합니다. JSON은 분석·보관용이며 세션 복원 기능은 없습니다. 수동 비교는 최근 결과를 유지하므로 다른 실험 전 CSV로 저장하세요.

실제 자료·질문·답변·시나리오·리포트는 저장소 밖 또는 `datasets/`, `scenarios/`, `evaluation_results/`, `local_dev/`, `uploads/`, `data/`, `reports/`, `sessions/`에 보관합니다. 이 폴더는 TXT/Markdown을 포함해 무시됩니다. `.env`, Secrets, 자료 PDF/PPTX/XLSX/CSV/JSON, 캐시·임시 파일도 제외합니다. 이미 추적한 파일에는 무시 규칙이 적용되지 않으므로 공개 전 `git status`를 확인하고 `git add -f`로 실제 자료를 넣지 마세요.

## 자동 테스트와 한계

```bash
pip install -r requirements-dev.txt
python -m pytest -q
```

공개 UI·Q&A 흐름·개발 기능 미노출·개발 실행 가드·반복 조건·미래 답변/평가 데이터 유출 방지·내보내기·기존 파서를 테스트합니다. SDK 테스트도 모의 HTTP이며 실제 API 요청은 하지 않습니다. 실제 사용자 자료의 과학적 정확성, 전문가와 평가 일치도, 실제 Community Cloud 업데이트, 동시 사용자 부하는 미검증입니다. 자세한 결과는 `VALIDATION.md`를 참고하세요.

## 주요 파일

```text
app.py                    공개 Q&A 연습만 제공
dev_app.py               localhost 개발자 평가·디버깅
qa/engine.py              두 앱이 공유하는 생성·피드백·품질 엔진
qa/prompts.py             검토된 공개용 추가 지침
qa/documents.py            PDF/PPTX 추출
qa/evaluation.py           과거 질문 독립 비교
qa/experiments.py          첫 질문 반복·동일 조건 비교·답변 시나리오 재생
qa/experiment_reports.py   개발용 자동 평가 리포트
qa/public_reports.py       공개용 Q&A 전용 다운로드
qa/dev_guard.py            개발 도구 로컬 실행 가드
qa/history.py              평가 질문 파일 파싱
qa/reports.py              기존 개발용 수동 리포트
examples/                  가상 질문 예시만 포함
tests/                     파서·분리·UI·반복 실행 테스트
```
